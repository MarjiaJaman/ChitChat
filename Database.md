# Database Schema — ChitChat

ChitChat uses **MySQL** as its database, managed by **Sequelize v6** with `underscored: true` (camelCase JS fields map to snake_case DB columns). On every server start, `sequelize.sync({ alter: true })` automatically aligns the schema with the models — no manual migrations needed.

---

## Tables

### `users`

Stores registered accounts.

| Column         | Type            | Constraints                  | Notes                                  |
|----------------|-----------------|------------------------------|----------------------------------------|
| `id`           | INT             | PK, AUTO_INCREMENT           | Auto-generated by Sequelize            |
| `full_name`    | VARCHAR(200)    | NOT NULL                     | JS field: `fullName`                   |
| `gender`       | ENUM            | NULL allowed                 | Values: `'Male'`, `'Female'`           |
| `date_of_birth`| DATE            | NULL allowed                 | JS field: `dateOfBirth`; date only, no time |
| `email`        | VARCHAR(255)    | NOT NULL, UNIQUE             |                                        |
| `password`     | VARCHAR(255)    | NOT NULL                     | bcrypt hash (cost factor 10)           |
| `profile_photo`| LONGTEXT        | NULL allowed                 | JS field: `profilePhoto`; MinIO URL stored as text |
| `created_at`   | DATETIME        | NOT NULL                     | Set by Sequelize on insert             |
| `updated_at`   | DATETIME        | NOT NULL                     | Updated by Sequelize on save           |

---

### `messages`

Stores every message exchanged between users.

| Column       | Type      | Constraints              | Notes                                         |
|--------------|-----------|--------------------------|-----------------------------------------------|
| `id`         | INT       | PK, AUTO_INCREMENT       | Auto-generated by Sequelize                   |
| `sender_id`  | INT       | NOT NULL, FK → users(id) | JS field: `senderId`                          |
| `receiver_id`| INT       | NOT NULL, FK → users(id) | JS field: `receiverId`                        |
| `content`    | LONGTEXT  | NOT NULL                 | Plain text or a prefixed special format (see below) |
| `is_read`    | TINYINT(1)| NOT NULL, DEFAULT 0      | JS field: `isRead`; `false` = unread, `true` = read |
| `sent_at`    | DATETIME  | NOT NULL                 | Sequelize `createdAt`; no `updatedAt` on messages |

---

## Relationships

```
users (1) ──< messages (N)   [sender_id → users.id]
users (1) ──< messages (N)   [receiver_id → users.id]
```

A conversation between two users is the set of all messages where `(sender_id, receiver_id)` is either `(A, B)` or `(B, A)`.

---

## Message Content Format

The `content` column stores plain text for regular messages. Special message types use a prefix so the frontend knows how to render them.

| Prefix          | Format                                                  | Renders as              |
|-----------------|---------------------------------------------------------|-------------------------|
| `__IMG__:`      | `__IMG__:https://...`                                   | Single photo            |
| `__PHOTOS__:`   | `__PHOTOS__:["https://...","https://..."]`              | Photo gallery           |
| `__PDF__:`      | `__PDF__:{"name":"filename.pdf","url":"https://..."}`   | Attachment download link|
| `__CALL__:`     | `__CALL__:{"type":"missed\|ended","duration":"mm:ss","time":"hh:mm"}` | Call record |
| *(no prefix)*   | Any plain string or URL                                 | Text message            |

All media URLs point to MinIO object storage (bucket: `chitchat`). In production/Docker the frontend accesses them through the backend proxy route `GET /api/proxy?url=<encoded>` to avoid CORS issues.

## Sequelize Field-Name Mapping

`underscored: true` is set on both models, which means:

| JavaScript (JS) | Database column |
|-----------------|-----------------|
| `fullName`      | `full_name`     |
| `dateOfBirth`   | `date_of_birth` |
| `profilePhoto`  | `profile_photo` |
| `senderId`      | `sender_id`     |
| `receiverId`    | `receiver_id`   |
| `isRead`        | `is_read`       |
| `sentAt`        | `sent_at`       |

When accessing a message instance in code, use the JS camelCase names (`msg.senderId`, `msg.isRead`) — but the timestamp `createdAt` is overridden to `sent_at`, so access it as `msg.sent_at` (or `msg.dataValues.sent_at`).
